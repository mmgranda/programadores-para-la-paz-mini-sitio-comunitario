Escribe el procedimiento para que otra persona pueda ejecutar el proyecto.

1. Requisitos del entorno

¿Qué debe tener instalado la persona?
Ejemplos: Git, Node.js, navegador, editor de código.

Respuesta: La persona debe tener instalado un entorno de ejecución de JavaScript como Node.js (con su gestor de paquetes npm), el sistema de control de versiones Git, un editor de código fuente (como Visual Studio Code) y un navegador web moderno (como Google Chrome, Microsoft Edge o Mozilla Firefox).

2. Clonar repositorio

Comando:

Respuesta: git clone https://github.com/mmgranda/programadores-para-la-paz-mini-sitio-comunitario.git

3. Entrar a la carpeta del proyecto

Comando:

Respuesta: cd programadores-para-la-paz-mini-sitio-comunitario

4. Crear o cambiar a rama personal

Comando:

Respuesta: git checkout marien_segura

5. Instalar dependencias

Comando:

Respuesta: npm install

6. Ejecutar el proyecto

Comando:

Respuesta: npm run sitio

7. Abrir en navegador

Dirección:

Respuesta: http://localhost:3000

8. Probar rutas de la API

Escribe las rutas que se deben probar:

Respuesta: Se deben verificar las siguientes direcciones desde el navegador o herramientas de pruebas:
- http://localhost:3000/api/mensajes (Para ver los mensajes del sitio)
- http://localhost:3000/api/calendario (Para ver los eventos programados)
- http://localhost:3000/api/resumen (Para obtener los datos generales)

9. Probar login pedagógico

Usuario de demostración: docente

Clave de demostración: demo

Resultado esperado: El servidor valida los datos mediante la ruta POST /api/login, el frontend procesa la respuesta afirmativa guardando el estado en el localStorage y la interfaz muestra una bienvenida interactiva al entorno educativo.

10. Verificación final

¿Cómo sabe la persona que el proyecto está funcionando?

Respuesta: Lo sabe de dos formas: primero, porque en la terminal o CMD aparece el mensaje "Mini-sitio comunitario funcionando en http://localhost:3000". Segundo, porque al entrar al navegador se carga de manera correcta la página web visual y las rutas de la API devuelven datos en formato JSON en vez de errores de conexión.

11. Nota de seguridad

¿Qué información NO debe publicarse?

Respuesta: Bajo ninguna circunstancia se deben publicar credenciales reales de administración, contraseñas personales, tokens de acceso privados de GitHub, llaves de API confidenciales o datos personales de los miembros del equipo de desarrollo. Todo debe mantenerse bajo los parámetros de simulación pedagógica.
